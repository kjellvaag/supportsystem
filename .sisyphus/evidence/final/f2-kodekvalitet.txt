Oppsummering
------------
Alle tre bygg-targets (fallback .xlsx, excel .xlsm, calc .ods) genereres uten feil.
Test-suiteen passerer med 17/17 tester. soffice-valideringen passerer begge round-trip.
Koden er i hovedsak velstrukturert, norsk, og følger planens arkitektur.
Det finnes noen mindre kvalitetsissues (hardkodede literaler, ubrukt import,
korrupt tegn i testfil, manglende automatisk knappetilknytning i .ods), men ingen
av dem er funksjonelle blokkerere. Verdikt: APPROVE med noterte forbedringspunkter.

Byggkommandoer
--------------
  python lag_supportsystem.py              -> EXIT 0, Supportsystem.xlsx generert
  python lag_supportsystem.py ren          -> EXIT 0, Supportsystem.xlsx generert (tomt)
  python lag_supportsystem.py --target excel -> EXIT 0, Supportsystem.xlsm generert
  python lag_supportsystem.py --target calc  -> EXIT 0, Supportsystem.ods generert
  python lag_supportsystem.py --target excel ren -> EXIT 0, Supportsystem.xlsm generert (tomt)
  python lag_supportsystem.py --target calc ren  -> EXIT 0, Supportsystem.ods generert (tomt)

Test-suite
----------
  python -m pytest test_struktur.py -v     -> 17 passed, 0 failed, EXIT 0

soffice-validering
------------------
  python valider_soffice.py                -> PASS (2/2 round-trip), EXIT 0
  Merk: Første kjøring under parallell bygg-test rapporterte FAIL for ODS->XLSX
  (utdatafil ikke produsert, exit 1). Ved isolert re-kjøring passerer begge
  konverteringer. Dette indikerer en tidsingsfølsomhet/race rundt soffice-launcher
  når flere prosesser berører filene samtidig, ikke en strukturell feil.

Kjente åpne tråder (vurdert)
-----------------------------
1. VBA-trefffarge-konstant (15652731 vs 10284031)
   STATUS: RETTET I KILDE.
   vba/ModSok.bas linje 25 har nå: Private Const FARG_TREFF As Long = 10284031
   (kommentar: RGB(255, 235, 156)). basic/ModSok.bas bruker 16771996, som er
   korrekt UNO/StarBasic-verdi for samme farge.
   MERK: vba/vbaProject.bin er en ekstrahert binær; den faktiske fargen i
   .xlsm avhenger av at donor er gjenbygget etter kilden ble rettet. Kildekoden
   er korrekt, men binæren er ikke verifisert byte-nivå i denne reviewen.

2. Manglende automatisk knappetilknytning i .ods
   STATUS: ÅPEN, DOKUMENTERT.
   Supportsystem.ods inneholder Basic-moduler (Module1-4.xml) og manifest-entries,
   men content.xml har <office:scripts/> uten hendelser, og det finnes ingen
   <form:button>-kontroller eller script:event-tilknytninger. Søk, tidsstempel
   og dashboard er derfor knapp-triggeret og må knyttes manuelt i Calc (dokumentert
   i basic/README.md og README.md). Dette følger planens design for LibreOffice/
   OpenOffice (ingen Worksheet_Change), men det er en reell brukeropplevelsesbegrensning.
